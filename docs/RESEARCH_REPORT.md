В рамках развития проекта **Antigravity Unlocker (`gravity-def`)** был произведен полный анализ исходного кода трёх ключевых сторонних репозиториев:

2. [**`confeden/Antigravity`**](https://github.com/confeden/Antigravity) (Rust)
3. [**`trustybird/agy-unlock`**](https://github.com/trustybird/agy-unlock) (Python / Shell / PowerShell)

Все три проекта были склонированы в изолированную рабочую директорию `research/`.

## 🔍 2. Детальный разбор каждого проекта

### 2.1. `trustybird/agy-unlock` (Python-стек)
Репозиторий представляет собой высокооптимизированную одиночную утилиту `patcher.py` (3000+ строк, 125 КБ), не требующую внешних библиотек.

#### Сильные стороны и уникальные фичи:
1. **Глубокий поиск установленных копий (`find_all_targets`)**:
   - Опрашивает реестр Windows: `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall`, `HKLM\...` и `WOW6432Node\...`, извлекая реальные `InstallLocation`.
   - Ищет приложения Scoop (`%USERPROFILE%\scoop\apps`, `%SCOOP%\apps`).
   - Проверяет директорию `~/.gemini/bin` (начиная с IDE 2.6+, расширение скачивает автономный `agy` именно туда).
   - На macOS проверяет `/opt/homebrew/bin/agy` (для Apple Silicon).
2. **Поддержка Electron `app.asar` и очистка V8-кэша**:
   - Читает структуру заголовков ASAR напрямую без node.js (`asar_read_entry_ex`).
   - **Очистка скомпилированного байткода**: после модификации `main.js` принудительно удаляет папки `CachedData` и `Code Cache/js` в `%APPDATA%\Antigravity IDE`. Без этого V8 продолжает исполнять закэшированный байткод со старыми проверками региона.
3. **Режим самообучения (`learn`)**:
   - Если Google выпускает новую версию `language_server` и старые байтовые сигнатуры не совпадают, алгоритм `learn` дизассемблирует и ранжирует кандидаты условных переходов (`jz`/`jnz`/`cbz`), автоматически находя новые смещения гейтов.
4. **Фоновый демон автопатчинга (`daemon`)**:
   - На Windows регистрирует задачу в Планировщике задач Windows (`schtasks /create /sc ONLOGON`) с запуском через `pythonw.exe` (без всплывающего черного окна консоли). Если прав на `ONLOGON` нет, ставит задачу с триггером каждые 30 минут.
5. **Диагностический модуль `cmd_doctor`**:
   - Сканирует динамические логи IDE (`%APPDATA%\Antigravity\logs\<сессия>\ls-main.log`).
   - Анализирует разделение доменов: предупреждает пользователя, если модельные домены идут через прокси, а домены аутентификации (`accounts.google.com`) идут напрямую и аккаунт заблокирован по стране профиля.

### 2.2. `confeden/Antigravity` (Rust-стек)
Полноценный системный комплекс от автора Brent (`t.me/nova_txt`), написанный на чистом Rust с графическим интерфейсом на `egui`/DirectX 12.

#### Сильные стороны и уникальные фичи:
1. **Изоляция прокси через переименование переменной окружения (`patch_proxy_var`)**:
   - В стандартной поставке Go-модуль `golang.org/x/net/http/httpproxy` проверяет пару переменных `HTTPS_PROXY` и `https_proxy`.
   - Если записать системный `HTTPS_PROXY=127.0.0.1:53129`, ломаются другие системные утилиты (git, curl, npm, pip), а при падении прокси весь ПК теряет сеть.
   - Автор заменяет в бинарнике строку `https_proxy` (11 байт) на **`AG_LS_PROXY`** (11 байт).
   - В результате: `language_server` направляется на локальный прокси через `AG_LS_PROXY`, а глобальный системный `HTTPS_PROXY` остаётся нетронутым!
2. **Мониторинг живых ответов модели через лог (`ls_log.rs`)**:
   - Внешний TCP/TLS-пинг проверяет только рукопожатие, но не знает, ответит ли нейросеть (Google отдаёт ошибку 400/403 внутри зашифрованного HTTP/2).
   - Модуль непрерывно отслеживает `language_server.log`:
     - Строка успеха: `.../v1internal:streamGenerateContent?alt=sse Trace: 0x... ResponseID: ...`. Появление `ResponseID` — это единственный 100% достоверный факт успешного ответа модели.
     - Строка отказа: `FAILED_PRECONDITION (code 400): User location is not supported` или `403 PERMISSION_DENIED: UNSUPPORTED_LOCATION`.
3. **Обход сторонних VPN через `IP_UNICAST_IF` (`socket2`)**:
   - Если у пользователя включен рабочий VPN (например, корпоративный или для других сайтов), он может перехватывать запросы анлокера.
   - Через `socket2` сокеты анлокера жестко привязываются к физическому сетевому интерфейсу провайдера (`IP_UNICAST_IF`), гарантируя прямой выход.
4. **Отказ от внедрения собственного корневого сертификата (No CA)**:
   - Проект использует чистый HTTP CONNECT туннель без MITM/расшифровки TLS. Это исключает падение Desktop-приложения с ошибкой `BadCertificate` и гарантирует безопасность пользовательских данных.
5. **Компиляция GUI без внешних DLL**:
   - Использование `eframe` (egui) со строго ограниченным бэкендом DirectX 12 (`wgpu dx12`) на Windows исключает падения на машинах с битыми Vulkan-драйверами и обеспечивает мгновенный старт без установки WebView2 или GTK.

*Примечание по этике*: Проект содержит экран проверки лицензии (`license.rs`), требующий ввода бесплатного ключа из Telegram-канала. Для нашего репозитория это неприемлемо, наш код должен работать без искусственных преград.

### 2.3. `vezlin1/antigravity-bypass-russia` (Rust-стек)
Инженерно выверенный системный проект на Rust с фокусом на надежность, безопасность отката и сетевую производительность.

#### Сильные стороны и уникальные фичи:
1. **Транзакционный журнал изменений (`system/journal.rs`)**:
   - Перед любой модификацией файла создается запись с SHA-256 хешами оригинала и патча (`current.json`).
   - Если целевой файл был обновлен Google во время работы, откат **никогда не перезапишет** обновленный файл старым бэкапом, предотвращая повреждение IDE.
2. **Оптимизация сетевого стека ОС (`net::socket::tune_os_network_stack`)**:
   - Трафик Gemini Code Assist и gRPC стриминга чувствителен к TCP Window Size и задержкам повторной передачи.
   - Утилита настраивает стек Windows через `netsh int tcp set global`:
     - `autotuninglevel=normal` (устраняет искусственное зажатие буфера приема в Windows);
     - `fastopen=enabled` (TCP Fast Open — отправка данных в пакете SYN, экономит 1 RTT);
     - `hystart=enabled` и `prr=enabled` (ускорение выхода на максимальную скорость и быстрое восстановление при потерях пакетов);
     - `ecncapability=enabled` (явное уведомление о перегрузке без сброса пакетов).
3. **Split-DNS на уровне платформенных резолверов**:
   - На Windows: точечные правила NRPT для модельных доменов.
   - На macOS: файлы в `/etc/resolver/<домен>` с привязкой только к локальному релею.
   - На Linux: интеграция с `systemd-resolved` через D-Bus/`resolvectl`.
4. **Модуль пассивного статуса модели (`model_status.rs`)**:
   - Читает последние 256 КБ лога без блокировки файлов, формирует структурированный статус (`StreamStarted`, `RegionBlocked`, `VerificationRequired`, `NoRecentEvents`) и позволяет выгружать отчет в JSON (`report`).

## 🎯 3. Что конкретно мы берём в наш проект (`gravity-def`)

На основе проведенного анализа сформирован план внедрения лучших инженерных решений в наш проект:

### 🚀 Этап 1: Клиентский патчинг и изоляция прокси (Высокий приоритет)
1. **Внедрение патча `https_proxy` -> `AG_LS_PROXY`**:
   - Добавить в `tools/unlocker_core.py` функцию `patch_proxy_var()`.
   - Заменять `https_proxy` (11 байт) на `AG_LS_PROXY` (11 байт).
   - **Результат:** `language_server` перенаправляется на локальный прокси или SNI-релей изолированно, не ломая `git`, `curl` и системный интернет пользователя.
2. **Расширение реестра поиска бинарников (`tools/unlocker_core.py`)**:
   - Взять алгоритм сканирования из `patcher.py`: опрос реестра Windows (`Uninstall\...\InstallLocation`), каталогов `scoop/apps`, каталога `~/.gemini/bin/` (для Antigravity 2.6+).
3. **Очистка V8-кэша (`Code Cache/js`, `CachedData`)**:
   - Добавить в `unlocker_core.py` автоматическую очистку кэшей IDE после патчинга, предотвращая запуск устаревшего байткода.

### 🌐 Этап 2: Сетевой стек и Smart Failover (Средний приоритет)
4. **Оптимизация TCP-стека Windows (`tools/unlocker_core.py`)**:
   - Добавить безопасную функцию тюнинга сетевого стека через `netsh int tcp set global autotuninglevel=normal fastopen=enabled`.
   - Сохранять исходное состояние для чистого отката (Rollback).
5. **Продвинутый мониторинг логов (`tools/diagnostics.py` и `gui_app.py`)**:
   - Внедрить детектор реального ответа модели из `ls_log.rs`: парсинг строки `streamGenerateContent?alt=sse ... ResponseID: ...`.
   - Отображать в GUI понятный статус: *"Модель отвечает (зеленый)"* / *"Блокировка региона (красный)"* вместо простого пинга порта.

### 🛡️ Этап 3: Фоновая служба и автоматизация обновлений (Автономность)
6. **Фоновый автопатчер через Планировщик Windows (Task Scheduler)**:
   - Добавить в CLI и GUI команду установки задачи в Планировщик Windows (`schtasks`), запускающей проверку и автопатч при старте системы через `pythonw.exe`.
   - При обновлении Antigravity IDE патч применится автоматически без участия пользователя.
